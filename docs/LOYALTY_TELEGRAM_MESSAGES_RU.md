# Уведомления о лояльности — вариант 2 и эффект 🎉
Дата: 9 октября 2026. Реализация в M-Pos-Backend. APK и project_bot не требуют изменений: backend использует существующий TELEGRAM_BOT_TOKEN для доставки в личный чат привязанного клиента.

## Обычная покупка
Пример при required_quantity=5 и progress=3:

> Спасибо за покупку!
>
> Ваш прогресс по акции «6-й кофе в подарок»:
> ● ● ● ○ ○ — 3 из 5
>
> Ещё 2 товара по акции — и подарок ваш 🎁

Цифры берутся из действующих настроек и итогового серверного состояния программы. Название акции не определяет порог: «6-й кофе» означает подарок после 5 оплаченных кофе только если так настроено required_quantity. Считаются подходящие товары, а не число чеков. Для нескольких программ в одном сообщении идут отдельные секции. До 10 единиц каждый кружок соответствует единице; при большем пороге индикатор имеет 10 сегментов и всегда сопровождается точным числом.

## Новый подарок
> Поздравляем! Вам доступен подарок 🎉
>
> Акция «6-й кофе в подарок»
> ● ● ● ● ● — 5 из 5
>
> Условия акции выполнены — подарок ваш 🎁
> Выберите подарок при оформлении заказа.
>
> Накопление продолжится после использования подарка.

Полный индикатор показывает выполненное условие, а не изменение базы: по существующим правилам при выдаче подарка progress сбрасывается и накопление приостанавливается. После использования подарка показывается прогресс следующего цикла. Уже доступный подарок обозначается без нового поздравления и эффекта. Формулы, схема БД и начисления не менялись.

## Эффект и доставка
[Telegram Bot API sendMessage](https://core.telegram.org/bots/api#sendmessage) поддерживает message_effect_id только в личных чатах. Для 🎉 используется строковый ID 5046509860389126442; соответствие подтверждено [документацией библиотеки Telekit](https://github.com/Romashkaa/telekit/blob/main/docs/tutorial2/5_senders.md#effects). Telegram не публикует фиксированный перечень этих ID в таблице sendMessage.

Эффект добавляется только если среди новых событий есть granted > 0 и получатель — личный числовой Telegram-ID. Повторные события duplicate исключаются. При явном ответе 400 об ошибке эффекта выполняется одна повторная отправка того же текста без эффекта. Общие ошибки, блокировка бота и таймаут не повторяются автоматически: доставка могла состояться до потери ответа, и повтор создал бы дубль. Запрос ограничен 10 секундами; каждая попытка имеет отдельный лимит.

Не включаются платные рассылки и не отправляются отдельные GIF/стикеры. Воспроизведение зависит от клиента Telegram и его настроек анимации; на старом клиенте текст остаётся читаемым. Транспорт проверяет также JSON ok, а не только HTTP-статус. Журнал ошибок не содержит токен, URL запроса, ID клиента или текст уведомления. Долговечная очередь повторной доставки этим этапом не добавлена.

## Проверка и ввод в работу
Обновлены проверки формата и добавлены тесты индикатора, нескольких программ, повторных событий, выдачи/использования подарка, выбора эффекта, fallback, блокировки и неоднозначного сетевого сбоя. Локальные тесты не запускались по договорённости: выполняются в GitHub Actions.

Внедрение требует развёртывания backend на новой ревизии; новое APK не требуется. После деплоя проверить на тестовом клиенте: обычная покупка, достижение порога, повтор синхронизации, использование подарка. Физическая доставка и показ 🎉 пока не подтверждены. Агент реальных сообщений клиентам не отправлял.

Этап: 3/3 — 100% реализации (формат, эффект/доставка, тесты/документация). CI, деплой и проверка Telegram — отдельные статусы.
