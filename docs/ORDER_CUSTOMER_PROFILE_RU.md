# Клиент текущего заказа: последние четыре цифры и подарок

Поиск текущего заказа отправляет ровно четыре последние цифры, backend фильтрует normalized_phone по окончанию (%NNNN), клиент повторно проверяет endsWith. Совпадения показываются отдельными карточками: имя и полный номер; автоматического выбора нет. Вставка полного номера извлекает последние четыре цифры. Device authentication и лимит 20 сохраняются; общие административные запросы по имени/префиксу работают как прежде.

Username загружается из customer loyalty API. Справа сверху в профиле — «Написать в Telegram», disabled при отсутствии валидного username. При смене клиента предыдущий username сразу очищается. Android открывает native Telegram через уже существующий host handler. Сообщение автоматически не отправляется.

Доступный подарок выбирается чекбоксом «Использовать подарок в этом заказе». Отдельное пояснение показывает применённый подарок либо необходимость добавить подходящий товар; названия берутся из локального каталога. Действующие JS allocation, сохранение заказа и серверная проверка при оплате сохранены. Выбор чекбокса не списывает подарок немедленно.

Изменения UI внесены в авторитетный iPad source и синхронизированы штатным sync-pos-assets.py. Новые/обновлённые регрессии проверяют suffix, несколько совпадений, Telegram validation и состояния подарка. Локальные тесты/lint/APK не запускались по пользовательской спецификации. CI и приёмка планшета pending до подтверждения.

Приёмка: поиск 4567 находит все окончания 4567; выбрать клиента, повторно открыть профиль, Telegram справа сверху; чекбокс без подходящего товара показывает подсказку, с товаром — применённый подарок, снятие возвращает обычную сумму. Проверить отсутствие username, отсутствие связи и смену клиента.
